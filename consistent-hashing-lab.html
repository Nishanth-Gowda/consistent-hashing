Consistent Hashing Lab

Blobasaur splits each node's data across several SQLite files and uses multi-probe consistent hashing to decide which file gets each key. Change the number of shards and watch how many keys have to move.

Why not hash % N

Changing N changes the answer for almost every key. Going from 4 to 5 shards moves about 80% of the data.

Why not a plain ring

Only about 1/(N+1) of keys move, but with one point per shard the arcs are uneven, so some shards get far more keys than others.

Virtual nodes fix load, at a cost

Giving each shard 100+ points evens the arcs, but the ring now holds N×100 entries to store and search.

Multi-probe keeps the ring small

One point per shard. Each key is hashed k times and goes to whichever shard is closest after any probe. With k = 1 it is the plain ring; more probes even out the load.
